# MinIO 控制台的生产访问

文件资产页面不提供控制台跳转，文件资产接口也不返回控制台地址。仅移除按钮不会关闭已经暴露的网络端口；部署时还需核对主机监听、容器端口映射、反向代理与安全组。

## 默认方式：内网控制台 + 临时 SSH 隧道

MinIO S3 API 和管理控制台是独立入口。标准生产模板只将 S3 的 9000 绑定到主机回环地址，控制台的容器端口 9001 不发布到公网。AIO 的内部控制台默认使用 19001，不能照搬独立容器的端口。

1. 在生产主机确认实际部署模式、MinIO 容器和监听端口。使用已有运维 SSH 账号，通过容器 inspect 查看网络地址，不打印环境变量或凭据。多网络容器应选择生产主机能够访问的那个内网地址。
2. 保持当前容器与数据卷不变，在本地建立临时隧道。以下尖括号内容为占位符，替换后使用：

```sh
ssh -N -o ExitOnForwardFailure=yes \
  -L '127.0.0.1:19001:<MinIO容器内网IP>:9001' \
  '<运维账号>@<生产主机>'
```

SSH 连接的目标主机必须能够访问该容器地址。若控制台已通过回环端口发布，转发目标可改为该主机的 `127.0.0.1:<实际控制台端口>`。若尚无可达路径，先调整受控运维网络；不要为了访问控制台改成 `0.0.0.0:9001`。

3. 在本地浏览器打开 `http://127.0.0.1:19001`，使用独立、权限受限的运维账号登录。若配置了浏览器重定向地址，先确认其与当前访问方式兼容。
4. 完成维护后退出账号并关闭 SSH 隧道。

不要将 MinIO root 凭据放入 URL、前端、文档或日志。直接从控制台删除、覆盖文件可能绕过平台资产元数据和业务审计，日常文件管理应继续走平台入口。

## 将来需要常驻入口时

使用私网域名或 VPN，并在反向代理前设置身份验证与访问范围限制、HTTPS、独立受限账号。S3 API 与控制台分别配置，不能因为 S3 上传需要公网访问而同时公开管理控制台。本文不自动修改生产防火墙、端口或账号。
