# 用户冻结、批量创建与公开链接管理

## 本次范围

不新增登录历史、最近活动时间或每次请求写入用户活动的逻辑。

### 账户冻结

系统用户管理沿用 `active / pending / disabled` 状态。调整状态时填写操作原因。

- 非 active 状态：在 HR 数据库事务内更新账户、停用所有会话、吊销用户的所有 OpenAPI Token，并保存 `user_status_event` 操作记录。
- 事务失败整体回滚。事务成功后发送网关失效通知；通知失败返回明确提示，可再次执行相同的停用操作补发。
- 网关正常接收通知后清除对应缓存；通知不可达时现有认证缓存最长一分钟。已开始执行的业务请求不会被回滚。
- 恢复账户不会恢复旧会话或被吊销的 API Token，需要重新登录或新建 Token。
- 新会话和新 API Token 的签发与冻结锁定同一用户行，避免冻结过程中新签发凭证的竞态。
- `system` 账户不能停用。操作记录只在管理员调整状态时写入，不记录高频用户活动。

模型由 HR 现有模型初始化流程迁移。上线应同时更新 HR 与前端。

### Excel 批量创建

入口：系统用户管理 → 批量创建用户。

1. 下载 `.xlsx` 模板。列为 `username, password, nickname, email, department_full_path`。
2. 用户名和密码必填；所有单元格使用文本格式，不接受公式或数字型密码。
3. 上传限制为 1 MB、100 个用户；前端解析后向 HR 提交有界 JSON。预览调用不会创建账户。
4. 后端逐行检查用户名、密码、邮箱、组织、文件内重复项和现有账户。
5. 确认创建可通过校验的行，显示逐行成功/失败。账号默认冻结，管理员分发凭证后再启用。
6. 失败后重新校验或修正文件再上传。已有用户名不会被覆盖或重设密码；如果请求中断，不要据此认定整批都失败，重新校验即可识别已存在账户。

接口：`POST /hr/api/v1/system/users/import`，参数 `rows` 和 `preview`，仅 system 可调用。密码不包含在导入结果中，也不保存在浏览器持久化存储中。当前版本不发送邀请、不自动分发密码、不实现首次登录强制改密。

### 公开链接

当前表单的分享管理支持勾选、确认后批量关闭。每个请求继续执行已有资源写权限检查。部分失败会提示重新选择重试；关闭保留历史提交。

列表与筛选区分：可用、已关闭、已过期、已达提交上限。访客打不开表单时显示友好状态和刷新入口，不直接展示底层错误。

冻结个人账户不会自动关闭工作空间的公开链接。管理员应在对应表单中显式关闭相关链接，避免因冻结协作者而误关团队业务。本次未新增跨工作空间全局链接管理页，也未改变匿名访客提交内容的返回协议。

## 验证

- HR 测试覆盖冻结事务回滚、通知重试、恢复后凭证仍失效、冻结账户无法签发新凭证、批量预览不写库和重试不覆盖密码。
- 分享仓库测试覆盖“可用”和“已达上限”筛选互斥。
- Excel 实际读写测试覆盖文本密码保真、拒绝公式、拒绝数字密码和文件大小限制。
- 前端类型检查、生产构建和针对修改文件的 ESLint 检查。

这些是本地代码与测试验证，不代表已经部署或对真实用户执行操作。
